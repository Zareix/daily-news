## 🔒 CYBERSÉCURITÉ & FUITES DE DONNÉES

### ☕ Java4Shell (CVE-2026-114938) : RCE non authentifiée sur Jira, Jenkins, Keycloak

Une faille critique d'OpenJDK, baptisée Java4Shell, permet à un attaquant sans compte d'exécuter du code sur Jira, Jenkins, Keycloak et trois autres applications d'entreprise très répandues. Oracle publie le même jour des correctifs pour onze vulnérabilités de Java SE, toutes exploitables à distance sans authentification.

- **Sources** : [The Hacker News](https://thehackernews.com/2026/11/java4shell-cve-2026-114938-enables-pre.html) · [BleepingComputer](https://www.bleepingcomputer.com/news/security/critical-java4shell-flaw-allows-rce-attacks-on-major-java-applications/) · [The Hacker News](https://thehackernews.com/2026/11/oracle-to-patch-11-java-flaws-today-as.html)

### 📦 Le paquet PyPI agent-framework de Microsoft compromis

Des attaquants ont compromis le paquet `agent-framework` de Microsoft pour y diffuser un voleur d'identifiants, selon sept laboratoires concordants dont Socket, Endor Labs et StepSecurity. La cible : les clés cloud des développeurs qui installent le paquet dans un cadre d'agents IA.

- **Source** : [The Hacker News](https://thehackernews.com/2026/11/attackers-compromise-microsofts-agent.html)

### 🐳 Les clés cloud laissées dans des images Docker Hub volées en huit secondes

Des identifiants et secrets d'accès exposés dans des images publiques Docker Hub sont extraits et exploités en huit secondes seulement après publication, par des robots de scan automatisés. Toute image poussée avec un `.env` ou des credentials en dur est donc compromises quasi instantanément.

- **Source** : [BleepingComputer](https://www.bleepingcomputer.com/news/security/cloud-keys-leaked-in-docker-hub-images-are-stolen-within-seconds/)

### 🇯🇵 Le supercalculateur Fugaku mis hors ligne après une intrusion

Le supercalculateur Fugaku, exploité par le centre RIKEN au Japon, a été déconnecté à la suite d'une compromission de sécurité. Les détails de l'attaque n'ont pas été publiés, mais l'arrêt d'une machine de cette classe illustre la pression sur les infrastructures de recherche.

Le projet Tor a livré un correctif de sécurité pour son logiciel de relais afin d'absorber un déni de service distribué en cours qui sature les relais. Les opérateurs de nœuds sont invités à mettre à jour sans attendre.

## 🚨 À appliquer sans attendre

1. **Java4Shell (CVE-2026-114938)** : mettre à jour le JDK sur toutes les instances Jira, Jenkins, Keycloak et autres applications Java exposées, en priorité celles accessibles depuis internet. Vérifier les journaux d'exécution inhabituelle côté serveurs d'intégration.
2. **Paquet PyPI `agent-framework`** : vérifier les environnements de développement et CI qui l'ont installé, puis faire tourner immédiatement les clés cloud (AWS, Azure, GCP) et jetons exposés.
3. **Images Docker Hub** : purger tout `.env`, secret ou jeton en dur des images publiques et considérer comme compromises toutes les clés qui y ont figuré.
4. **iPhone/iPad** : installer la dernière mise à jour de sécurité système, la faille de permission micro est corrigée.
5. **Nœuds Tor** : mettre à jour le logiciel de relais pour encaisser le DDoS en cours.
