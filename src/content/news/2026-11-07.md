## 🇫🇷 FRANCE

### ✊ Quatrième samedi de mobilisation sous haute tension

Gilets jaunes, syndicats et lycéens manifestent à nouveau ce samedi 7 novembre, pour un quatrième week-end consécutif de contestation contre la vie chère. ### 👻 Libghostty 1.0 : le moteur de terminal de Ghostty devient une bibliothèque

Mitchell Hashimoto publie la version 1.0 de libghostty, qui extrait le cœur du terminal Ghostty sous forme de bibliothèque réutilisable. L’objectif est de permettre à d’autres projets — éditeurs, IDE, outils maison — d’embarquer un émulateur de terminal complet plutôt que de réimplémenter la gestion des séquences d’échappement.

- **Sources** : [mitchellh.com](https://mitchellh.com/writing/libghostty-1-0) · [HN (531 pts)](https://news.ycombinator.com/)

### 🗄️ GitHub refonte son architecture de stockage Git

GitHub détaille en interne la nouvelle architecture qui stocke les objets Git de ses dépôts, pensée pour absorber la croissance du nombre de dépôts et de leur taille. L’article revient sur les compromis retenus côté stockage et sur la migration progressive de l’existant.

- **Sources** : [GitHub Blog](https://github.blog/engineering/architecture-optimization/inside-githubs-new-git-storage-architecture/) · [HN (126 pts)](https://news.ycombinator.com/)

## 🔒 CYBERSÉCURITÉ & FUITES DE DONNÉES

### 🛡️ SonicWall : contournement de la MFA SSL-VPN exploité dans la nature

SonicWall publie des correctifs pour sept vulnérabilités de SonicOS, dont un contournement d’authentification SSL-VPN permettant de passer outre la double authentification, déjà exploité en attaques. Les pare-feu exposés sur Internet doivent être mis à jour en priorité, puis les journaux SSL-VPN examinés à la recherche de connexions anormales.

- **Source** : [BleepingComputer](https://www.bleepingcomputer.com/news/security/sonicwall-warns-of-new-ssl-vpn-mfa-bypass-flaw-exploited-in-attacks/)

### 🗝️ Claude Code : les règles « Don’t Ask Again » fuient des secrets sur GitHub

Des mots de passe et clés d’API saisis dans des commandes validées par les utilisateurs de Claude Code se retrouvent dans des fichiers de configuration poussés sur GitHub : 1 122 copies publiques ont été identifiées. Le mécanisme « Yes, and don’t ask again » enregistre l’autorisation, et donc parfois les secrets qu’elle contenait.

- **Source** : [The Hacker News](https://thehackernews.com/2026/11/claude-codes-dont-ask-again-file.html)

### 🐚 OpenSSH « SSHole » : exploitation en quelques heures, root obtenu sur un honeypot

La faille récemment divulguée dans OpenSSH permet de se connecter à des comptes sans mot de passe défini, et des attaquants ont tenté de l’exploiter dans les heures suivant la publication. Des chercheurs ont obtenu un accès root sur un serveur honeypot ; les systèmes exposés doivent être patchés sans attendre.

- **Source** : [The Hacker News](https://thehackernews.com/2026/11/hackers-exploited-openssh-sshole-flaw.html)

### 🧾 Chainalysis : les identifiants de tous les clients exposés

La société d’analyse blockchain Chainalysis confirme qu’une cyberattaque « agentique » contre ses systèmes internes a exposé noms, identifiants, hachages de mots de passe et jetons encore valides de l’ensemble de ses clients. Plusieurs services ont dû être coupés, et les clients doivent considérer leurs jetons comme compromis.

- **Sources** : [The Hacker News](https://thehackernews.com/2026/11/chainalysis-breach-exposes-all-users.html) · [BleepingComputer](https://www.bleepingcomputer.com/news/security/chainalysis-says-breach-exposed-credentials-for-all-customers/)

### 🖥️ QNAP : la chaîne Plex2Shell utilisée pour compromettre des NAS

QNAP confirme que des attaquants exploitent la chaîne de vulnérabilités Plex2Shell pour s’introduire sur des NAS via Plex Media Server. L’éditeur demande de mettre à jour Plex vers la dernière version disponible dans le QNAP App Center ; l’exposition directe du service sur Internet reste le principal facteur de risque.

- **Source** : [BleepingComputer](https://www.bleepingcomputer.com/news/security/qnap-says-hackers-breaching-nas-devices-in-plex2shell-attacks/)

## 🚨 À appliquer sans attendre

1. **SonicWall SonicOS** — appliquer les correctifs des sept vulnérabilités, en particulier le contournement de la MFA SSL-VPN exploité ; restreindre l’accès VPN aux adresses connues et relire les logs de connexion.
2. **OpenSSH « SSHole »** — patcher immédiatement, désactiver l’authentification par mot de passe vide sur les comptes de service et vérifier les comptes sans mot de passe défini.
3. **Plex Media Server sur NAS QNAP** — mettre à jour via le QNAP App Center (chaîne Plex2Shell) et ne pas exposer l’interface Plex directement sur Internet.
4. **Claude Code** — auditer les fichiers de configuration contenant les autorisations « Don’t Ask Again », révoquer et faire tourner toute clé ou tout mot de passe qui y figure, et vérifier qu’aucun dépôt public ne les contient.
5. **Microsoft Paint (CVE-2026-83844)** — le correctif RCE n’arrive que par le Microsoft Store, pas par Windows Update : déclencher la mise à jour de l’application manuellement.
6. **D-Link DGS-3130** — plusieurs failles zero-day non corrigées : appliquer les mesures d’atténuation publiées et isoler les switches du réseau en attendant un firmware.
