## 🇫🇷 FRANCE

### 🗳️ Présidentielle 2027 : l'offensive illibérale du RN

Les dirigeants du Rassemblement national multiplient les attaques publiques contre les corps intermédiaires : associations, syndicats, magistrats et journalistes. ## 🔒 CYBERSÉCURITÉ & FUITES DE DONNÉES

### 🔧 N-able N-central : le 0-day « 4EverAble2Shell » exploité en quelques heures

Des attaquants exploitent activement une faille zero-day de N-able N-central, baptisée « 4EverAble2Shell », quelques heures seulement après la publication d'une preuve de concept, pour compromettre des serveurs et y déployer des mineurs de cryptomonnaies. Vingt et un serveurs sont touchés, dont dix-neuf fonctionnant pourtant avec le correctif HF2, et un second jeu de failles (« Agent2Shell ») permet un accès root ou SYSTEM. N-able restreint désormais certaines fonctionnalités de N-central et enquête.

- **Sources** : [BleepingComputer](https://www.bleepingcomputer.com/news/security/new-n-able-4everable2shell-zero-day-exploited-hours-after-poc-released/) · [The Hacker News](https://thehackernews.com/2026/11/new-n-central-exploits-work-against.html)

### 🪟 SignDrop : un 0-day Windows pour obtenir SYSTEM

Le chercheur Abdelhamid Naceri a publié une preuve de concept, « SignDrop », qui permet à un utilisateur Windows local d'élever ses privilèges jusqu'à SYSTEM en détournant une fonction de sécurité du pilote CLFS. Aucun correctif n'est disponible à ce stade. L'exploit est public, donc directement réutilisable.

- **Sources** : [BleepingComputer](https://www.bleepingcomputer.com/news/security/new-windows-signdrop-zero-day-gives-hackers-system-privileges/) · [The Hacker News](https://thehackernews.com/2026/11/new-signdrop-zero-day-exploit-turns.html)

### 🐙 GitHub : 4 800 comptes compromis pour voler des identifiants cloud

La campagne « wfx-loot » a utilisé 4 837 comptes GitHub compromis pour sonder 61 764 dépôts, ouvrir des pull requests et y pousser du code malveillant chargé de voler des secrets. Les cibles sont les jetons cloud et les variables d'environnement des projets. Un dépôt compromis suffit à atteindre l'infrastructure du propriétaire.

- **Source** : [BleepingComputer](https://www.bleepingcomputer.com/news/security/hackers-compromise-4-800-github-accounts-to-steal-cloud-credentials/)

### 🌐 Apache HTTP Server : RCE critique dans HTTP/2

Une vulnérabilité critique du module HTTP/2 d'Apache HTTP Server permet à un attaquant non authentifié d'obtenir une exécution de code à distance. Des correctifs sont publiés. Les serveurs exposant HTTP/2 en frontal sont concernés en priorité.

- **Source** : [BleepingComputer](https://www.bleepingcomputer.com/news/security/apache-http-server-patches-critical-http-2-remote-code-execution-flaw/)

### 🐋 Red Hat Quay : toutes les images privées lisibles et écrasables

Une faille critique de Red Hat Quay permet à un attaquant ayant accès à un registre de lire et d'écraser les images conteneurs privées de tous les dépôts. Quay autorise l'accès anonyme par défaut, ce qui élargit fortement la surface. Les registres internes non cloisonnés sont les plus exposés.

- **Source** : [The Hacker News](https://thehackernews.com/2026/11/critical-red-hat-quay-flaw-lets.html)

## 🚨 À appliquer sans attendre

1. **N-able N-central** : le correctif HF2 ne suffit plus contre « 4EverAble2Shell ». Couper l'exposition Internet de la console d'administration, restreindre les accès par liste blanche, chercher des mineurs et des tâches planifiées suspectes sur les serveurs N-central.
2. **Apache HTTP Server** : déployer la mise à jour corrigeant le RCE HTTP/2, ou désactiver le module `http2` en attendant sur les instances exposées.
3. **Citrix NetScaler** : 12 correctifs publiés, dont un contournement d'authentification sur NetScaler ADC, Gateway et Console — à appliquer avant toute autre fenêtre de maintenance.
4. **Red Hat Quay** : patcher et vérifier que l'accès anonyme n'est pas activé sur les registres internes ; auditer les images récemment modifiées.
5. **GitHub** : révoquer les jetons et secrets susceptibles d'avoir transité par une pull request externe, passer en revue les PR récentes des dépôts sensibles et généraliser les jetons à portée limitée et à durée courte.
6. **Windows** : pas de correctif pour SignDrop — limiter les comptes administrateurs locaux, surveiller les élévations de privilèges vers SYSTEM et les chargements inhabituels du pilote CLFS.
